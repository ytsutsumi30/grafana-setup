#### OCR精度向上戦略

##### ハイブリッドOCRアプローチ
```javascript
class OCREngineEnhanced {
  async recognize(image) {
    // 1. AWS Textract (クラウド高精度)
    const textractResult = await this.textractOCR(image);

    // 2. Tesseract.js (オフライン補完)
    const tesseractResult = await this.tesseractOCR(image);

    // 3. スコアリング・結果統合
    return this.mergeResults(textractResult, tesseractResult);
  }
}
```

##### 画像前処理パイプライン
- **グレースケール変換** - カラーノイズ除去
- **二値化処理** - 文字と背景の明確化
- **ノイズ除去** - スキャンノイズ・影の除去
- **傾き補正** - 斜め撮影の自動補正
- **コントラスト強化** - 薄い文字の視認性向上

### 3. モバイルQRスキャン検品システム

#### 機能概要
スマホ・タブレットのカメラで製品同梱物のQRコードをスキャンし、リアルタイムで検品状況を記録。iOS Safari完全最適化済み。

#### QR検品データモデル

##### データベーススキーマ
```sql
-- 製品同梱物マスタ
CREATE TABLE product_components (
    id SERIAL PRIMARY KEY,
    product_id INTEGER REFERENCES products(id),
    component_type VARCHAR(50) NOT NULL,  -- 'main', 'accessory', 'manual'
    component_name VARCHAR(255),
    qr_code VARCHAR(255) UNIQUE,
    is_required BOOLEAN DEFAULT true
);

-- QR検品記録
CREATE TABLE qr_inspections (
    id SERIAL PRIMARY KEY,
    shipping_instruction_id INTEGER,
    inspector_name VARCHAR(100),
    product_id INTEGER,
    total_components INTEGER,
    scanned_components INTEGER DEFAULT 0,
    passed_quantity INTEGER DEFAULT 0,
    status VARCHAR(50) DEFAULT 'in_progress',  -- 'completed', 'failed'
    completed_at TIMESTAMP
);

-- QR検品詳細（スキャン履歴）
CREATE TABLE qr_inspection_details (
    id SERIAL PRIMARY KEY,
    qr_inspection_id INTEGER,
    product_component_id INTEGER,
    qr_code VARCHAR(255),
    scanned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(50) DEFAULT 'scanned'  -- 'error', 'duplicate'
);
```

## ⚠️ リスクと対策

### 技術リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| AWS障害 | 高 | Multi-AZ構成、自動フェイルオーバー |
| OCR精度不足 | 中 | ハイブリッドOCR、手動補正UI |
| iOSカメラ非対応 | 中 | フォールバックUI、jsQRライブラリ |
| データ移行エラー | 高 | 段階的移行、ロールバック計画 |

### 運用リスク

| リスク | 影響度 | 対策 |
|--------|--------|------|
| 現場の抵抗感 | 中 | 丁寧なトレーニング、操作マニュアル |
| ネットワーク障害 | 高 | オフライン動作モード実装 |
| コスト超過 | 低 | CloudWatch予算アラート設定 |
| セキュリティ侵害 | 高 | IAM厳格化、VPC制限、暗号化 |

### 対策の詳細

#### AWS障害対策
```
- Multi-AZ RDS構成（自動フェイルオーバー）
- ALBによる複数EC2への負荷分散
- S3への自動バックアップ（日次）
- 別リージョンへのディザスタリカバリ
```

#### OCR精度向上策
```
- AWS Textract + Tesseract.js のハイブリッド
- 画像前処理パイプライン（傾き補正・ノイズ除去）
- 低精度時の手動補正UI
- 継続的な精度モニタリング
```

#### データ移行戦略
```
1. 並行稼働期間（2週間）
2. 段階的データ移行（製品→在庫→履歴）
3. ロールバックポイント設定
4. データ整合性チェックスクリプト
```
